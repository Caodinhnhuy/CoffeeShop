 5. Repository Pattern The RP separates business logic from data access logic, promoting a loose couple between the two layers. This makes it easier to maintain and test the application. Benefit:  Abstraction layer promptes loose coupling  Easier maintenance and testing  Flexibility in data storage and retrieval Repository Interface  Play a crucial role in specifying the capabilities repository.  It outlines the operations (methods) supported, along with the data needed for each operation.  The interface defines the parameters and data that the method returns. public interface IProductRepository {  List<Product> GetProdcuts() {  //get products form the database } } Controller Class and Loose Coupling  The Controller class calls the methods of the Repository Interface instead of directly accessing the database.  This achieves loose coupling of the code Public class ProductController {  IProductRepository productRepository;  productController(IProductRepository productRepository) {   this.productRepository = productRepository;

4. Edit Repository Class 
Open ProductRepository.cs 
using coffeeshop.Data; 
using coffeeshop.Models.interfaces; 
 
namespace coffeeshop.Models.Services 
{ 
    public class ProductRepository : IProductRepository 
    { 
        private CoffeeshopDbContext dbContext; 
        public ProductRepository(CoffeeshopDbContext dbContext) 
        { 
            this.dbContext = dbContext; 
        } 
 
        public IEnumerable<Product> GetAllProducts() 
        { 
            return dbContext.Products; 
        } 
 
        public Product? GetProductDetail(int id) 
        { 
            return dbContext.Products.FirstOrDefault(p => p.Id == id); 
        } 
 
        public IEnumerable<Product> GetTrendingProducts() 
        { 
            return dbContext.Products.Where(p => p.IsTrendingProduct); 
        } 
    } 
}
